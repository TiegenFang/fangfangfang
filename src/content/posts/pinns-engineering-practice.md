前七讲解决「会不会写」，这一讲解决「能不能复现」。PINNs 的可复现性口碑很差，很大一部分原因不是方法本身，而是实验记录不完整：采样点没存、权重没记、只报单次运行的最优值。这一讲给出一套从选库到复现清单的完整流程。

## 库对比

| 库                     | 后端                       | API 抽象层次              | 域分解/变体支持        | 批训练与多 GPU     | 文档与社区           | 许可证              | 适合规模   |
| ---------------------- | -------------------------- | ------------------------- | ---------------------- | ------------------ | -------------------- | ------------------- | ---------- |
| DeepXDE [1]            | TensorFlow / PyTorch / JAX | 高：声明几何 + PDE + 边界 | 有：多域与部分变体内置 | 依赖后端           | 最全，示例多         | Apache-2.0          | 中小       |
| NVIDIA PhysicsNeMo [2] | PyTorch                    | 中：图式配置              | 有：图式多物理场组合   | **强：多节点扩展** | 官方文档全，社区中   | Apache-2.0          | **大**     |
| NeuroDiffEq [3]        | PyTorch                    | 高：函数式声明            | 弱                     | 单卡               | 简，上手快           | 以仓库 LICENSE 为准 | 小（原型） |
| IDRLnet [4]            | PyTorch                    | 中                        | 有：反问题接口         | 单卡               | 中文文档友好         | 以仓库 LICENSE 为准 | 中小       |
| SciANN [5]             | Keras / TensorFlow         | 中：函数式                | 弱                     | 单卡               | 中                   | 以仓库 LICENSE 为准 | 中小       |
| PINNacle [6]           | PyTorch                    | 基准套件而非求解器        | 评测多种配置           | —                  | 含统一误差度量与协议 | 以仓库 LICENSE 为准 | 评估用     |

**命名说明**：NVIDIA 这个框架先后叫 SimNet、Modulus，现名 **PhysicsNeMo**（PyPI 包 `nvidia-physicsnemo`）。文献 [2] 是该研究线的早期论文，只能代表方法源头；表中的能力描述与接口以现名官方文档为准。检索文献时三个名字都要试，只搜现名会漏掉 2020–2023 年的工作。

两点提醒。第一，PINNacle 不是求解器，是**基准**：当你怀疑「是我的实现问题还是方法上限」时，用它跑同一问题做对照最省事。第二，许可证列只填了有公开把握的两项，其余以各仓库 LICENSE 为准——它很少成为决定因素，但商用项目必须逐核。

选库的实质是选**抽象层次**：抽象越高，写方程越快，但自定义损失项（第 6、7 讲那种带归一化与锚定的损失）越别扭。若你的损失函数有特殊结构，宁可选抽象低一点的库或直接写原生 PyTorch。

## 采样策略

| 策略                 | 做法                         | 适用                             | 配点量级参考             |
| -------------------- | ---------------------------- | -------------------------------- | ------------------------ |
| 均匀                 | 域内等距或均匀随机           | 光滑、无薄层问题                 | $10^3\sim10^4$           |
| LHS                  | 拉丁超立方，分层降方差       | 高维域                           | 同均匀                   |
| 边界加密             | 边界单独取样，密度高于内部   | 几乎所有问题                     | 边界点不少于内部点的 10% |
| 区域分级             | 按物理结构分区，梯度大区加密 | 薄层、锋面、边界层（第 6、7 讲） | 锋面区占 60–80%          |
| 残差自适应（RAR 类） | 预热后在残差最大处加点       | 先验不知道结构在哪               | 迭代中追加 1–2 轮        |

通用建议：**先区域分级，再残差自适应**。区域分级用物理先验（你知道锋面在哪），残差自适应补先验漏掉的部分。纯均匀采样在薄层问题上几乎必然失败，见第 6 讲的失败模式表。

## 优化实践

- **两段式**：Adam 粗调（$10^4\sim10^5$ 步）→ L-BFGS 精调（$10^3\sim10^4$ 步）。L-BFGS 是拟牛顿法，在全批梯度下收敛快一个量级以上；但它对初值敏感，直接上会陷进坏局部解，所以必须 Adam 先铺路。理由见第 2 讲。
- **学习率调度**：Adam 段用余弦或指数衰减；观察到某损失项停滞时再降一档。ReduceLROnPlateau 可用，但监控指标要选**分项损失**而非总损失。
- **批大小**：配点少于 $10^4$ 时直接全批；更多时用 minibatch，但 L-BFGS 段必须切回全批。
- **早停判据**：不要用总损失。用「验证配点上的残差中位数连续 N 轮不降」，N 取 50–100。

## 验证与误差度量

- **相对 $L_2$ 误差**：$\lVert u_\theta - u_{\mathrm{ref}}\rVert_2 / \lVert u_{\mathrm{ref}}\rVert_2$，报告时说明参考解来源（解析解 / 高保真 CFD / 实验）。
- **$L_\infty$ 误差**：暴露局部最差区域。$L_2$ 好看但 $L_\infty$ 很差，通常意味着锋面或边界没学好。
- **残差场的空间分布图**：比任何标量都有信息量。残差均匀小才算收敛；局部尖峰说明该区域欠拟合，即使总损失很小。
- **跨随机种子统计**：至少 5 个种子，报均值与标准差。单次运行的最优值没有意义——这是 PINNs 文献里最常见的不可复现来源。
- 与参考解的**逐点对比曲线**，而不只是误差数字：能看出是整体偏移还是局部失效。
- **参考解的选择纪律**：参考解必须独立于被评方法、且精度高一到两个量级。用同阶方法作参考会把系统误差对消，给出虚假的小误差；若只有实验可作参考，必须同时报告实验不确定度——否则 $10^{-3}$ 的「误差」可能全部是测量噪声，而你会据此宣称方法达到了它并没有达到的精度。

## 复现清单

每次实验记录以下八项，缺任何一项都视为不可复现：

1. 随机种子（网络初始化 + 采样）。
2. 配点坐标文件（存盘，不要靠种子重新生成——换库或换版本后随机序列会变）。
3. 全部损失权重与归一化系数。
4. 迭代数、优化器切换点、早停判据与实际触发轮次。
5. 学习率与调度参数。
6. 库与后端版本（PyTorch / TensorFlow / JAX 及 CUDA 版本）。
7. 硬件与墙钟训练时长。
8. 参考解来源与误差度量定义。

**填写示例**（1D 反应–扩散，第 3 讲 walkthrough 的同一个问题）：

1. 种子：`[0,1,2,3,4]`（采样与初始化共用序列，分别记录偏移）。
2. 配点：`colloc_v3.npz`，$N_r=8000$（锋面区 4800）、边界 100、RAR 追加 1200。
3. 权重：$\lambda_r=\lambda_b=1$；源项按 $Da_k$ 归一化后统一权重；无数据项。
4. 迭代：Adam 60000 步 → L-BFGS 8000 步；早停判据「验证残差中位数 80 轮不降」，实际第 63 轮触发。
5. 学习率：$10^{-3}$ 余弦衰减至 $10^{-5}$。
6. PyTorch 2.x + CUDA 12.x（以实验机实际为准，写入环境导出文件）。
7. 单卡 A 类 GPU，墙钟 41 分钟（含两轮 RAR）。
8. 参考解：谱方法 $N=2048$；误差为相对 $L_2$ 与 $L_\infty$，报 5 种子均值 ± 标准差。

这份示例的价值不在数字，而在**形态**：每一项都具体到可以被另一个人执行。若你的清单里出现「默认设置」「调了好久」这类词，它就是不可复现的。

## 常见踩坑

| 症状                       | 根因                           | 处理                                            |
| -------------------------- | ------------------------------ | ----------------------------------------------- |
| 某损失项恒为主导，其余不降 | 漏做无量纲化或归一化           | 回第 2 讲做量级估算；按第 6、7 讲的归一化方案补 |
| 残差很小但边界条件不满足   | 边界配点太少，边界项被淹没     | 边界加密 + 监控边界项梯度范数                   |
| 总损失小但解不对           | 残差配点集中在低残差区，假收敛 | 画残差场；上残差自适应采样                      |
| 早停太早或太晚             | 用总损失做早停指标             | 改用验证配点残差中位数                          |
| 结果别人复现不出           | 只报单次最优、没存配点         | 按复现清单补齐；报多种子统计                    |
| 多工况评估训练成本爆炸     | 用 PINNs 做算子该做的事        | 换神经算子（FNO / DeepONet），见第 4、5 讲      |
| 误差被系统性低估           | 训练配点与测试配点同源         | 测试配点独立生成，密度高于训练                  |

最后一条尤其隐蔽：用同一批配点既算损失又报误差，得到的「精度」毫无参考价值。测试集必须独立采样。

## 反例解剖：一份不可复现的报告长什么样

下面这段是虚构的，但每个短语都来自真实论文或技术报告：

> 「我们使用 PINN 求解了该问题。网络为 4 层 512，训练 100k 步，最终相对误差 1.2e-3，优于基线方法。」

逐句解剖：

- **「4 层 512」**：缺激活函数、缺初始化方案、缺输入是否做 Fourier 映射。同样「4 层 512」，tanh 与 sin 激活、有无 RFF，结果可以差一个量级。
- **「训练 100k 步」**：缺优化器、缺 Adam→L-BFGS 切换点、缺早停判据与实际触发轮次。100k 步 Adam 与 60k+8k 两段式是两种完全不同的实验。
- **「相对误差 1.2e-3」**：缺参考解来源（解析？CFD？实验？）、缺度量定义（$L_2$ 还是 $L_\infty$？全域还是子域？）、缺种子数。单种子 1.2e-3 与五种子均值 1.2e-3 ± 0.9e-3 是两种结论。
- **「优于基线」**：基线是什么？同预算吗？基线若是一个未调参的粗网格，「优于」没有信息量。

改写版（八项齐全，篇幅只多一倍，信息量多一个量级）：

> 「网络 4 层 512 tanh，输入经 $\sigma=1.5$ 的 RFF 映射；Adam 60k 步（lr 1e-3 余弦至 1e-5）后 L-BFGS 8k 步全批；早停判据为验证残差中位数 80 轮不降，5 个种子中 3 个于 61–67k 步触发。配点 8000 均匀 + 出口边界层 1500 + 初始线 300，存于 colloc_v3.npz。参考解为谱方法 N=2048；全域相对 $L_2$ 为 1.2e-3 ± 0.4e-3（5 种子），$L_\infty$ 为 6.8e-3 ± 2.1e-3，最差位置在出口边界层。基线为同墙钟预算（41 min/种子）下的二阶 FVM 均匀网格 400×400，其 $L_2$ 为 3.9e-3。」

两版的差异不在字数，而在**可执行性**：第二版的每个数字都能被另一个人复算或质疑，第一版不能。评审时遇到第一版，正确的反应不是相信 1.2e-3，而是索要清单。

## 小结

工程实践的核心不是调参技巧，而是**记录纪律**。PINNs 的方差大是方法特性，无法消除；但「方差大」和「不可复现」是两回事——前者报多种子统计即可，后者是记录缺失。把复现清单当成实验的一部分而不是事后补的文档，这门课的方法才真正可用。
